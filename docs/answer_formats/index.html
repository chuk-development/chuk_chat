chuk_chat · Konzept · Antwortformat

Antworten, die besser aussehen als Markdown

Kein Klick, kein Regler, kein zweiter Modell-Aufruf. Das Modell schreibt die Antwort in einem Durchgang in einem erweiterten Markdown. Die App setzt sie wie ein Datenblatt oder eine Magazinseite.

1Statisch. Alles ist auf einen Blick lesbar. Nichts wartet auf eine Eingabe.
2Zeilenbasiert. Halb gestreamt rendert es schon richtig. Ohne Renderer bleibt es lesbarer Text.
3Günstig. Kein JSON, keine Klammern, keine Escapes. Im Schnitt weniger Zeichen als die Markdown-Antwort.
Referenz

Die Syntax

Normales Markdown gilt weiter. Dazu kommen acht Zeilen-Regeln und zwölf Blöcke. Es gibt nur drei Trennzeichen: : trennt Schlüssel und Wert, | trennt Spalten, -> zeigt ein Ergebnis.

Regeln fürs Streamen

  1. Eine Zeile wird erst gesetzt, wenn ihr Zeilenumbruch da ist. Bis dahin steht sie als grauer Text da.
  2. ::: name öffnet einen Block. Er rendert sofort mit den Zeilen, die schon da sind. ::: schließt ihn. Fehlt das, schließt ihn der nächste Block oder das Ende der Nachricht.
  3. Blöcke werden nicht verschachtelt. Ein Fehler kostet höchstens eine Zeile, nie die ganze Antwort.
  4. Ein unbekannter Block oder eine kaputte Zeile wird als normales Markdown gezeigt. { ohne } bleibt Text.
Zwölf echte Fragetypen

Heute gegen Neu

Die Fragen kommen aus der Analyse von 939 eigenen Chats, gekürzt und ohne private Daten. „Heute“ ist eine typische Markdown-Antwort, so wie die App sie jetzt zeigt. „Neu“ ist derselbe Inhalt im neuen Format. Unter jeder neuen Antwort steht der Text, den das Modell dafür streamt.

    Halb gestreamt

    Dieselbe Antwort wie in Beispiel 03, nach etwa 60 % der Zeichen angehalten. Der Block ist offen, die letzte Zeile ist noch nicht fertig. Trotzdem steht schon ein sauberes Bild da. Ein halbes <compare>{"items":[… mit JSON zeigt an dieser Stelle noch gar nichts.

    Die Inhalte der Beispiele zeigen das Format. Sie sind nicht geprüft, Nachrichten und Öffnungszeiten sind erfunden.
